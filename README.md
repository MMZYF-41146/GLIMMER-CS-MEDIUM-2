## Step 1：甜度与温控传感器

### 一、到底有多甜？
寄存器读出来的原始二进制是：`1001 1100`
**（1）按无符号整数解析**
甜度值 = **156**
**（2）按有符号补码解析**
最高位是 1，说明是负数。求绝对值要"取反再加一"：
甜度值 = **-100**（也就是"少糖 100 档"）
**（3）为什么计算机都用补码，不用原码/反码？**
1. **0 只有一种表示。** 原码和反码里 +0 和 -0 编码不同（如原码 `00000000` 和 `10000000` 都是 0），浪费编码且比较时要额外判断。补码的 0 唯一，8 位刚好表示 -128~127 共 256 个数。
2. **减法可以变成加法。** x - y 直接算 x + (y 的补码)，硬件只需要一个加法器。
3. **符号位可以跟着一起运算。** 不用单独处理符号，进位自然前传，电路规整。
4. **溢出很好判断。** 同号两数相加，结果符号与操作数不同即溢出，一个异或门即可检测。
5. **位扩展很自然。** 有符号数符号扩展、无符号数零扩展，规则统一，混合字长运算不易出错。

### 二、冰块引发的火灾警报
**程序运行后输出：**
```
[警告!] 温度过高！触发消防喷淋系统！
```
**原因分析**
问题在这一行：
```c
if (current_temp < warning_temp)   // int 和 unsigned int 比大小
```
`current_temp` 是 `int`，`warning_temp` 是 `unsigned int`。C 语言规定：**有符号整数和无符号整数比较或运算时，有符号的一方会被隐式转换成无符号数**。
所以 -10 被当成无符号数解读：
```
(unsigned int)(-10) = 2^32 - 10 = 4294967286
```
实际比较的是 `4294967286 < 50`，结果为假，进入 else 分支。机器把 -10℃ 看成了四十多亿度。

## Step 2：反物质珍珠

### 一、、算术溢出的惨剧
已有 88 颗：`0101 1000`，再加 65 颗：`0100 0001`
- **寄存器实际位模式**：`1001 1001`
- **系统认为的珍珠数**：最高位为 1，是负数。取反加一：`0110 0110 + 1 = 0110 0111 = 103`，所以是 **-103 颗**。
- **溢出类型**：**正溢出**。两个正数相加结果为负。判据为"同号相加，结果符号与操作数不同"；等价于最高数值位进位与符号位进位异或为 1。
```c
/*
 * 判断两个 32 位有符号 int 相加是否溢出
 * 不发生溢出返回 1，发生溢出返回 0
 */
int is_safe(int x, int y) {
    int sum      = x + y;
    int x_sign   = (x >> 31) & 1;
    int y_sign   = (y >> 31) & 1;
    int sum_sign = (sum >> 31) & 1;
    int result;

    /* TO DO */
    if (x_sign == y_sign && sum_sign != x_sign)
        result = 0;          /* 同号相加却变号 -> 溢出 */
    else
        result = 1;          /* 异号不可能溢出；同号不变号则安全 */
    /* END OF TO DO */

    return result;
}
```

## Step 3：丝滑配比阀 —— IEEE 754 浮点数
### 一、学长的思考
1. **float 和 double 的位数分配**
| 格式 | 总位数 | 符号位 S | 阶码 E | 尾数 f | Bias |
|---|---|---|---|---|---|
| float（单精度） | 32 | 1 | 8 | 23 | 127 |
| double（双精度） | 64 | 1 | 11 | 52 | 1023 |
2. 偏置公式：`Bias = 2^(k-1) - 1`，k 为阶码位数。
**为什么阶码要加 Bias 再存？**
阶码字段按无符号整数存储，没有符号位。真实指数 e 加上 Bias 后存入，保证存入的值永远非负。好处：① 硬件只需无符号比较器；② 同符号的两个浮点数，整串二进制当作无符号整数比较，大小关系与真值一致，排序比较可用整数指令完成；③ 全 0 和全 1 被空出，用于表示 ±0、非规格化数、∞、NaN。
3. **非规格化数的特点（阶码字段全 0）**
- 隐含前导位由 1 变为 **0**，尾数为 `0.f`；
- 真实指数固定为 `e = 1 - Bias`（不是 -Bias，见 3.3）；
- 值 = (-1)^s × 0.f × 2^(1-Bias)。
作用：能表示比最小规格化数更接近 0 的数；实现**渐进下溢**，使 0 附近数值等间距分布，避免"再小一点就直接变 0"的精度断崖；尾数也全 0 时自然表示 ±0。
4. **两个特殊阶码模式（阶码全 1）**
| 情况 | 含义 |
|---|---|
| 阶码全 1，尾数全 0 | **±∞**（符号位决定正负），如除以 0 |
| 阶码全 1，尾数不全为 0 | **NaN**，如 sqrt(-1)、0/0、∞-∞ |

### 二、补全浮点数对照表
格式：S(1) E(4, Bias=7) M(3)。规格化：e=E-7，M=1.f；非规格化：e=-6，M=0.f。
| 二进制位模式 | 编码类型 | 实际阶码 e | 尾数真值 M | 十进制真值 |
|---|---|---|---|---|
| `0 0110 100` | 规格化 | -1 | 1.100₂ = 1.5 | 0.75 |
| `0 0000 011` | **(A) 非规格化数** | **(B) -6** | **(C) 0.011₂ = 0.375** | **(D) 3/512 = 0.005859375** |
| `0 1111 000` | **(E) 特殊值 → +∞** | 不适用 | 不适用 | **+∞** |
| `0 1001 010` | 规格化 | **(F) 2** | **(G) 1.010₂ = 1.25** | **(H) 5.0** |

### 三、阀门的极限
1. **非规格化数（e = -6）**
- 最小正非规格化数：`0 0000 001` → (1/8)×2⁻⁶ = **1/512 = 0.001953125**
- 最大非规格化数：`0 0000 111` → (7/8)×2⁻⁶ = **7/512 = 0.013671875**
2. **规格化数（阶码 1111 留给 ∞/NaN，最大取 1110）**
- 最大正规格化数：`0 1110 111` → e=7, M=1.875 → **240**
- 最小正规格化数：`0 0001 000` → e=-6, M=1.0 → **1/64 = 0.015625**
3.**为什么非规格化阶码是 1-Bias 而不是 -Bias？**
为了让两段**正好接上，中间不留缝**。最小正规格化数恒为 1.000×2^(1-Bias) = 8/512；若取 e = -Bias，最大非规格化数只有 0.111×2⁻⁷ = 7/1024，与规格化区间之间会出现空隙，0 附近间距也不均匀。采用 e = 1-Bias 后，最大非规格化数 = 7/512，与最小规格化数 8/512 恰好相邻，[0, 最小规格化] 区间内所有可表示数间距均为 1/512，实现了渐进下溢与均匀量化。

## Step 4：消失的营业额

### 一、八位迷你浮点加法器（思路）
步骤：对阶（小阶向大阶看齐，小阶尾数右移）→ 尾数相加 → 规格化（≥10.000 右规，<1.000 左规）→ 向零舍入（直接截断低 3 位）。
对阶必须"小阶向大阶看齐"，因为右移丢掉的是低位，精度损失可控；若反过来让大阶左移，会丢失高位有效数字甚至溢出尾数寄存器。
```c
/*
 * 哈吉蜜-26710 迷你浮点加法器
 * 格式：S(1) E(4, bias=7) M(3)
 * 步骤：对阶 -> 尾数相加 -> 规格化 -> 向零舍入 -> 输出 8 位二进制
 * 用法：每行输入两个 8 位二进制串（空格隔开），Ctrl+D 结束
 */
#include <stdio.h>

static void parse(const char *s, int *e, int *m)
{
    int v = 0;
    for (int i = 0; i < 8; i++)
        v = (v << 1) | (s[i] - '0');
    *e = ((v >> 3) & 0xF) - 7;
    *m = v & 0x7;
}

int main(void)
{
    char a[16], b[16];

    while (scanf("%15s %15s", a, b) == 2) {
        int e1, m1, e2, m2;
        parse(a, &e1, &m1);
        parse(b, &e2, &m2);

        if (e1 < e2) {                 /* 保证 e1 >= e2，小阶向大阶看齐 */
            int t; t = e1; e1 = e2; e2 = t;
            t = m1; m1 = m2; m2 = t;
        }

        int d  = e1 - e2;
        int M1 = 8 | m1;               /* 恢复隐含前导 1 */
        int M2 = (8 | m2) >> d;        /* 对阶右移，低位丢弃 = 向零舍入 */

        int S = M1 + M2;               /* 尾数运算 */
        int e = e1;

        while (S >= 16) { S >>= 1; e++; }   /* 右规 */
        while (S < 8 && e > -6) { S <<= 1; e--; }  /* 左规 */

        int E = e + 7;
        int m = S & 0x7;

        printf("%d%04d%03d\n", 0, E, m);
    }
    return 0;
}
```

### 二、老板为什么每天都在亏钱？
float 只有 24 位有效数字（约 6~7 位十进制），而 1e20 ≈ 2^66。在这个量级上相邻可表示 float 的间距：
```
ULP(1e20) ≈ 2^(66-23) = 2^43 ≈ 8.8 × 10^12
```
即在 1e20 附近 float **最小能分辨约 8.8 万亿**，15 块钱根本"挤不进去"。
**算法 1** `(boss_wallet + daily_expense) + milk_tea_price`：先算 1e20+(-1e20)，阶码相同尾数相减得精确 **0.0**，再加 15.0 → **15.0**。✅
**算法 2** `boss_wallet + (daily_expense + milk_tea_price)`：先算 -1e20+15.0，对阶时 15 的尾数需右移约 63 位，有效位全部被舍入丢掉，结果仍是 **-1e20**；再加 1e20 → **0.0**。❌
**结论**：浮点加法**不满足结合律**，根源是对阶右移丢位 + 有限精度下"大数吸收小数"，结果依赖运算顺序。同理也不满足分配律，且不能用 `==` 判相等。
